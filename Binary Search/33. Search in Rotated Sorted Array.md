# 33. Search in Rotated Sorted Array

## Pattern
Binary Search on Rotated Sorted Array

## Recognition
- Array is originally sorted.
- Rotated at an unknown pivot.
- All elements are **distinct**.
- O(log n) time expected.

## Core Idea
In every iteration, **one half of the array is always sorted**.

Determine which half is sorted:
- If `nums[low] <= nums[mid]` → Left half is sorted.
- Otherwise → Right half is sorted.

Then check whether the target lies in the sorted half:
- Yes → Search that half.
- No → Search the other half.

## Algorithm
1. Initialize `low = 0`, `high = n - 1`.
2. While `low <= high`:
   - Compute `mid`.
   - If `nums[mid] == target`, return `mid`.
   - Check which half is sorted.
   - Decide which half to search based on the target.
3. Return `-1` if not found.

## Pseudocode

```java
low = 0
high = n - 1

while(low <= high):

    mid = low + (high - low) / 2

    if(nums[mid] == target)
        return mid

    // Left half sorted
    if(nums[low] <= nums[mid]):

        if(nums[low] <= target && target < nums[mid])
            high = mid - 1
        else
            low = mid + 1

    // Right half sorted
    else:

        if(nums[mid] < target && target <= nums[high])
            low = mid + 1
        else
            high = mid - 1

return -1
```

## Key Syntax

```java
int mid = low + (high - low) / 2;

if(nums[low] <= nums[mid])

if(nums[low] <= target && target < nums[mid])

if(nums[mid] < target && target <= nums[high])

return -1;
```

## Complexity

Time: O(log n)

Space: O(1)

## Template Insight

Whenever:
- Rotated sorted array.
- Distinct elements.
- Need search in O(log n).

Think:
**Identify the Sorted Half → Check Target Range → Discard the Other Half**
