# 237. Delete Node in a Linked List

## Pattern
Linked List (In-Place Node Deletion)

## Recognition
- You are **not given the head** of the linked list.
- You are given **only the node to be deleted**.
- The node is **guaranteed not to be the last node**.

## Core Idea
Since the previous node is unknown, you **cannot bypass the current node**.

Instead:
1. Copy the value of the next node into the current node.
2. Skip the next node.

Effectively, the next node is deleted while the current node takes its value.

## Algorithm
1. Copy the next node's value to the current node.
2. Point the current node's `next` to `next.next`.
3. Done.

## Pseudocode

```java
node.val = node.next.val

node.next = node.next.next
```

## Key Syntax

```java
node.val = node.next.val;

node.next = node.next.next;
```

## Complexity

Time: O(1)

Space: O(1)

## Template Insight

Whenever:
- Head is **not available**.
- Need to delete a node.
- Node is guaranteed **not** to be the last node.

Think:

**Copy Next Node → Skip Next Node**

## Why Does This Work?

Original List:

```text
4 → 5 → 1 → 9
      ↑
    delete
```

Step 1:

Copy next node's value.

```text
4 → 1 → 1 → 9
      ↑
```

Step 2:

Skip the next node.

```text
4 → 1 → 9
```

The node with value `5` is effectively removed.

## Common Mistakes

❌ Trying to delete the node using:

```java
node = node.next;
```

This only changes the local reference and does **not** modify the linked list.

---

❌ Trying to access the previous node.

The previous node is **not available** in this problem.

---

❌ Applying this to the last node.

This solution works **only because the node is guaranteed not to be the last node**.
