# 203. Remove Linked List Elements

## Pattern
Linked List Traversal

## Recognition
- Remove all nodes having a given value.
- Nodes can appear anywhere (head, middle, tail).
- Head itself may need to be removed.

## Core Idea
There are two cases:

1. **Remove leading nodes** whose value equals `val`.
2. Traverse the remaining list:
   - If `current.next.val == val`, bypass that node.
   - Otherwise, move forward.

> This approach avoids using a dummy node while correctly handling head deletions.

## Algorithm
1. Remove matching head nodes.
2. If the list becomes empty, return `null`.
3. Traverse the list:
   - If `current.next.val == val`:
     - `current.next = current.next.next`
   - Else:
     - Move `current`.
4. Return the updated head.

## Pseudocode

```java
while(head != null &&
      head.val == val):

    head = head.next

current = head

while(current != null &&
      current.next != null):

    if(current.next.val == val):

        current.next = current.next.next

    else:

        current = current.next

return head
```

## Key Syntax

```java
while(head != null &&
      head.val == val)

head = head.next;

current.next = current.next.next;

current = current.next;

return head;
```

## Complexity

Time: O(n)

Space: O(1)

## Template Insight

Whenever:
- Delete nodes based on a condition.
- Head may also need deletion.

Think:

**Handle Head Separately → Traverse → Bypass Nodes**

## Common Mistakes

❌ Forgetting to remove matching head nodes.

```java
1 -> 1 -> 2
```

Removing `1` should produce:

```text
2
```

---

❌ Moving `current` after deleting.

Wrong:

```java
current.next = current.next.next;
current = current.next;
```

This may skip consecutive nodes.

Correct:

```java
current.next = current.next.next;
```

Do **not** move `current` after deletion.
