# 49. Group Anagrams

## Pattern
HashMap + String Encoding

## Recognition
- Group strings with the same characters.
- Order of characters doesn't matter.
- Need to identify equivalent strings.

## Core Idea
Generate a **unique key** for every string.

Two common approaches:

1. **Sort each string** → Sorted string becomes the key.
2. **Character frequency** → Frequency array becomes the key.

Strings with the same key belong to the same group.

> The sorting approach is simpler and the most commonly expected in interviews.

## Algorithm (Sorting Approach)
1. Create a `HashMap<String, List<String>>`.
2. For each string:
   - Convert to `char[]`.
   - Sort the array.
   - Convert back to a string (key).
   - Add the original string to the corresponding list.
3. Return all map values.

## Pseudocode

```java
map = {}

for(word : strs):

    chars = word.toCharArray()

    sort(chars)

    key = new String(chars)

    if(key not in map):
        map.put(key, new List)

    map.get(key).add(word)

return new ArrayList<>(map.values())
```

## Key Syntax

```java
HashMap<String, List<String>> map = new HashMap<>();

char[] chars = word.toCharArray();

Arrays.sort(chars);

String key = new String(chars);

map.putIfAbsent(key, new ArrayList<>());

map.get(key).add(word);

return new ArrayList<>(map.values());
```

## Complexity

### Sorting Approach
Time: O(n × k log k)

- `n` = number of strings
- `k` = average string length

Space: O(n × k)

### Frequency Array Approach
Time: O(n × k)

Space: O(n × k)

> The frequency-array approach is faster but requires creating a custom key from the 26-character counts.

## Template Insight

Whenever:
- Need to group equivalent strings.
- Equality depends on character frequency, not order.

Think:
**Generate a Unique Key → Store in HashMap**
